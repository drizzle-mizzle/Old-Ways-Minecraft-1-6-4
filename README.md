# Old Ways

Minecraft-сервер 1.6.4 на Spigot. Упор на градостроение и RPG-прокачку:
игроки основывают города и развивают их, растут в классах и навыках.
Войны, осады и политика нациями — не то, ради чего это собрано:
боевые механики Towny отключены в конфиге.

## Запуск

```
docker compose up -d
```

Сервер поднимется на `25565`.

```
docker compose logs -f              # лог
docker exec mc164 mc "op ВашНик"    # команда в консоль сервера
docker compose stop                 # остановка с сохранением миров
```

Вариант без Docker (Windows) — `start.bat`. Рядом с ним нужна портативная
Java 8 в папке `jre8/`; в репозиторий она не попадает, берётся с
[adoptium.net](https://adoptium.net/temurin/releases/?version=8&os=windows&arch=x64)
как JRE-zip и распаковывается под этим именем.

## Что внутри

| | |
|---|---|
| Ядро | Spigot 1.6.4-R2.1 на Java 8 |
| Города | Towny 0.88.0.0, TownyChat, Questioner |
| RPG | Heroes 1.5.5, 67 навыков, 6 классов |
| Права и экономика | zPermissions, Vault, Essentials |
| Остальное | WorldEdit, WorldGuard, NoCheatPlus, Chairs, MobHealthDisplay |

**Версии плагинов не обновлять.** Каждая подобрана под API 1.6.x; следующие
сборки этих же плагинов собраны под 1.7 и на 1.6.4 не запускаются.

## Как устроено

Образ — это релиз: ядро, плагины, эталонные конфиги. Том `/data` — состояние:
миры, города, прогресс игроков, права. Пересборка образа обновляет плагины
и не трогает нажитое.

В репозитории лежат только конфигурация, Docker-обвязка и jar-ники плагинов.
Миры, данные Towny и Heroes — нет.

## Лаунчер

Свой: авторизация, скины, докачка сборки, запуск игры. Java 8 + Swing,
без зависимостей, `launcher/`. Собирается одной командой (нужен JDK 8
в `jdk8/`, ставится как `jre8`):

```
python launcher/build.py
```

Игрок вводит логин и пароль — остальное лаунчер делает сам: качает
недостающие файлы по манифесту и сверяет хеши, раскладывает ресурсы, вписывает
адрес в клиент и запускает игру. Адрес сервера, выделенная память, автовход
и тема оформления — в настройках по кнопке в углу. Смена адреса не требует
новой раздачи: клиент пересобирается из базового.

Окно нарисовано по макету [files/ui_template.html](files/ui_template.html):
фон на весь кадр, матовое стекло, темы «день» и «ночь» (и «авто» по часам).
Картинки — в `files/`, готовые к вложению версии — в `launcher/resources/`.

Что нужно на сервере:

```
python tools/build_dist.py --out dist     # раздача из зеркала, ~119 МБ
docker compose up -d auth                 # сервис отдаёт её на 8080
```

Сервис авторизации поднимается вместе с сервером, порт 8080. Основной аккаунт
`flower` создаётся при первом старте; **пароль по умолчанию совпадает с ником**
— задайте свой в `OW_ADMIN_PASSWORD` до выхода наружу.

## Попробовать целиком на одной машине

Сервер, сервис авторизации и лаунчер поднимаются рядом и работают друг с другом.

**1. Раздача клиента** — один раз, из зеркала (`tools/fetch_client.py`, если
зеркала ещё нет):

```
python tools/build_dist.py --out dist
```

**2. Сервер и сервис.** Простой вариант — `docker compose up -d`: сервер
поднимется с `online-mode=false` и никого не проверяет, лаунчер при этом
работает. Чтобы сервер спрашивал разрешение у сервиса, как это будет в бою:

```
python tools/patch_jars.py --input spigot-1.6.4-R2.1.jar --output server-auth.jar --auth-base http://auth:8080 --skin-base http://auth:8080
docker compose -f docker-compose.yml -f docker/compose.online.yml up -d
docker exec mc164 sh -c "sed -i 's/^online-mode=false/online-mode=true/' /data/server.properties"
docker restart mc164
```

Сервер ходит к сервису по имени `auth:8080` внутри сети Docker, лаунчер на
хосте — на `localhost:8080`; служба одна и та же, поэтому рукопожатие сходится.

**3. Лаунчер.** Для себя хватит собранного jar:

```
python launcher/build.py
jre8\bin\javaw.exe -jar launcher\build\oldways-launcher.jar
```

Для раздачи игрокам — один exe, внутри которого лежит и Java:

```
python launcher/package.py
```
docker exec mc164 sh -c "sed -i 's/^online-mode=true/online-mode=false/' /data/server.properties"
docker compose up -d --force-recreate minecraft
```

## Раздача игрокам

`python launcher/package.py` собирает **Old Ways.exe** (23 МБ) — один файл,
внутри которого лежит Java 8 и сам лаунчер. Устанавливать нечего: при первом
запуске exe распаковывает рантайм и стартует, дальше запуск занимает доли
секунды.

Рядом с exe ничего не появляется — он остаётся одним файлом, который можно
держать хоть в «Загрузках». Всё нажитое живёт в папке приложения:

```
%LOCALAPPDATA%\Old Ways\runtime\    Java 8
%LOCALAPPDATA%\Old Ways\game\       клиент, ресурсы, настройки, миры
```

Дорогу туда показывает кнопка «Папка игры» в окне лаунчера. Удалить сборку —
стереть эту папку; больше от неё в системе ничего нет.

Масштаб окна лаунчера и стартовый размер окна игры берутся из настроек
Windows: на экране 4К при 175% всё выходит той же величины, что и на обычном
мониторе. Если хочется иначе — ключи `scale`, `game.width` и `game.height`
в `game/launcher.properties`.

Для сборки exe нужны два набора, которых нет в репозитории: `jdk8/` (как
`jre8`, но JDK — им собирается jar) и `mingw64/` (gcc, им собирается сам
запускатель). Ссылки — в шапке `launcher/package.py`.

Устройство и принятые решения — в [docs/launcher-wip.md](docs/launcher-wip.md).
Рядом: патчер джарников (`tools/patch_jars.py`) и зеркало набора запуска
клиента (`tools/fetch_client.py`), из которого собирается раздача.

## Важно

`online-mode=false`, белый список выключен. Для локальной игры это нормально,
но означает, что зайти можно под любым ником, включая ник оператора. Перед тем
как публиковать сервер наружу, включите whitelist или поставьте AuthMe.

распространение здесь не подразумеваются.
