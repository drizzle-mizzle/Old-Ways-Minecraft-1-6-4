# Лаунчер W-Factory — рабочие заметки

> Черновик. Решения по стеку приняты, код лаунчера ещё не начат.
> Из этого документа сделано пока только одно — патчер джарников
> (`tools/patch_jars.py`), он готов и проверен.

## Задача

Свой лаунчер: авторизация через наши аккаунты, скины, привязанные к аккаунту,
автообновление сборки, вшитые ресурспаки и моды. Позже — сайт для управления
аккаунтами, откуда лаунчер и скачивается.

Целевые системы: Windows 7 / 10 / 11 и Ubuntu 20.04+. Минимум телодвижений
у пользователя — скачал, поставил, играет.

## Главная находка

**В 1.6.4 нет authlib.** Клиент и сервер ходят за авторизацией и текстурами
по обычному HTTP на адреса, зашитые в байткод строковыми константами.
Ни подписей текстур, ни проверки ключей, ни UUID. Вся поверхность:

| Где | Класс | Константа |
|---|---|---|
| клиент | `bcw.class` | `http://session.minecraft.net/game/joinserver.jsp?user=` |
| клиент | `beu.class` | `http://skins.minecraft.net/MinecraftSkins/%s.png` |
| клиент | `beu.class` | `http://skins.minecraft.net/MinecraftCloaks/%s.png` |
| клиент | `jz.class` | `http://session.minecraft.net/game/checkserver.jsp?user=` (встроенный сервер) |
| сервер | `net/minecraft/server/v1_6_R3/ThreadLoginVerifier.class` | `http://session.minecraft.net/game/checkserver.jsp?user=` |

Аргументы запуска тоже простые: `--username X --session Y`, без accessToken.

То есть самая тяжёлая часть современных лаунчеров здесь почти отсутствует.
Побочный эффект: после переезда на свою авторизацию можно вернуть
`online-mode=true`, и сервер начнёт проверять игроков через наш сервис вместо
мёртвого мояновского — дыра «любой заходит под любым ником» закрывается.

## Почему не берём готовое

| Проект | Лицензия | Что даёт | Почему мимо |
|---|---|---|---|
| [GravitLauncher](https://github.com/GravitLauncher/Launcher) | GPL-3.0 | Авторизация, скины, обновления, сборки | Официально 1.7.10–1.20 |
| [Helios Launcher](https://github.com/dscalzi/HeliosLauncher) | MIT | Electron-оболочка, манифест раздачи, апдейтер | Авторизация под Mojang/Microsoft |
| authlib-injector, Drasl, Ely.by | open | Свой Yggdrasil | Требуют authlib, а он с 1.7.2 |

Граница экосистемы проходит по 1.7.10 — там Mojang ввела authlib и UUID.
Бэкпорт чужой архитектуры под 1.6.4 дороже, чем написать тонкий слой самим:
у нас на всю авторизацию четыре строки.

У Helios стоит позаимствовать формат манифеста раздачи и логику апдейтера —
лицензия MIT позволяет.

## Стек лаунчера

| | | Почему |
|---|---|---|
| Язык и UI | Java 8, Swing + [FlatLaf](https://github.com/JFormDesigner/FlatLaf) | В Temurin 8 JRE нет JavaFX (`jfxrt.jar` отсутствует), Swing есть всегда. FlatLaf — Apache-2.0, требует Java 8+, живой |
| Рантайм | Temurin 8u504 JRE, один на лаунчер и на игру | Игра требует Java 8 в любом случае. Пишем лаунчер на ней же — второй рантайм не нужен |
| Windows | Инсталлятор Inno Setup | Работает на 7/10/11 |
| Linux | tar.gz с `run.sh` | Сборки Temurin 8 собраны под старую glibc, Ubuntu 20.04 проходит |

Размеры: Windows x64 JRE 40,1 МБ, Linux x64 41,8 МБ — одна и та же версия.

**Electron и Tauri отпали из-за Windows 7.** Electron потерял поддержку Win7
на версии 23 (февраль 2023), последняя поддерживающая ветка 22 EOL в октябре
2023. Tauri упирается в WebView2: последний рантайм для Win7 — 109, без
обновлений, и его установщик на Win7 спотыкается о TLS 1.2.

## Слои

1. **Патч джарников** — один раз при сборке, результат кладётся в раздачу.
   Готово: `tools/patch_jars.py`.
2. **Сервис авторизации и скинов** — `joinserver.jsp`, `checkserver.jsp`,
   отдача PNG. Позже становится бэкендом сайта аккаунтов.
3. **Лаунчер** — манифест сборки с хешами, докачка, запуск клиента.

## Состояние патчера

`tools/patch_jars.py` переписывает константы в constant pool. Заменять можно
на строку любой длины: в class-файле константы адресуются по индексу, а не по
смещению, поэтому достаточно переписать пул и оставить остальное как есть —
ASM не нужен.

Клиентский jar подписан Mojang (`META-INF/MOJANGCS.SF`, `.RSA`), после правки
классов подпись становится недействительной. Патчер снимает её и вычищает из
`MANIFEST.MF` секции с хешами файлов — то же самое делают при установке модов
на 1.6.4. Серверный jar не подписан, там просто правка на месте.

Проверено:

- все четыре константы заменены, следов `minecraft.net` не осталось;
- патченные классы грузятся настоящим загрузчиком JVM (через `jjs` из JRE),
  `ClassFormatError` нет;
- патченный сервер стартует и останавливается штатно: 17 плагинов,
  ноль SEVERE, код выхода 0.

Боевой `spigot-1.6.4-R2.1.jar` в репозитории **не тронут** — патчить его имеет
смысл только когда появится сервис авторизации.

## Решение: раздаём готовую сборку

Рассматривались два варианта: лаунчер качает ванильный клиент у Mojang и
патчит его на машине игрока, либо мы раздаём уже готовый.

**Выбран второй.** Причина — доступность: Mojang может в любой момент
перестать раздавать легаси-версии, ровно как исчезли официальные сборки
CraftBukkit после DMCA и как сейчас доживают зеркала, с которых мы брали
ядро и Towny.

Следствие, которое легко упустить: рискует не один файл, а весь набор запуска,
и он лежит на трёх разных хостах Mojang.

| Компонент | Файлов | Объём | Хост |
|---|---|---|---|
| Клиент | 1 | 4,75 МБ | `launcher.mojang.com` |
| Библиотеки (LWJGL и пр.) | 18 | 7,78 МБ | `libraries.minecraft.net` |
| Нативы под все ОС | 7 | 2,33 МБ | `libraries.minecraft.net` |
| Ассеты (индекс `legacy`) | — | 153,48 МБ | `resources.download.minecraft.net` |
| | | **~168 МБ** | |

Ассеты — 90% веса. Без них и без библиотек пропатченный клиент не стартует,
так что зеркалировать надо весь набор.

Раз лаунчер и так раздаёт сборку со своего хоста, игрок к Mojang не ходит
вообще, и его исчезновение перестаёт что-либо значить.

### Где хранить

- **Репозиторий** — манифесты (`1.6.4.json`, индекс ассетов), патчер,
  список хешей. Текст, диффится, весит копейки.
- **GitHub Releases / свой хост** — сами байты, ~168 МБ. В git их лить нельзя:
  ассеты никогда не меняются, но осядут в истории навсегда и утяжелят каждый
  клон.

Ванильный клиент берётся отсюда, sha1 сверяется с манифестом Mojang —
это же и доказательство происхождения:

```
https://launcher.mojang.com/v1/objects/1703704407101cf72bd88e68579e3696ce733ecd/client.jar
sha1 1703704407101cf72bd88e68579e3696ce733ecd, 4 745 096 байт
```

Оригинал храним рядом с пропатченным: при добавлении модов патч
пересобирается от ванильного клиента, а не поверх предыдущего результата.

## Дальше

- Сервис авторизации: реализовать протокол `joinserver`/`checkserver` и отдачу
  скинов. Это следующий шаг, без него патч некуда направлять.
- Зеркалирование набора запуска: скачать 168 МБ по манифесту, сверить хеши,
  сложить в архив. Пока Mojang раздаёт — это делается в один заход.
- Домен. Сейчас адреса подставляются параметрами `--auth-base` / `--skin-base`.
  После патча они зашиты в клиент, и смена домена потребует передачи новой
  сборки — выбирать нужно один раз и надолго.
- Rei's Minimap: в 1.6.4 моды ставятся инъекцией классов в клиентский jar.
  Патчер уже умеет пересобирать jar, добавить в него установку модов несложно.
- Открыто: как лаунчер обновляет сам себя, и нужен ли отдельный bootstrap.
